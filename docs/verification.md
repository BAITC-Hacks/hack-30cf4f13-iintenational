# Протокол проверки редизайна — 23 сентября 2026

Проверен локальный проект после изменения интерфейса. Это протокол фактического
прогона, а не обещание отсутствия любых ошибок. Повторяемые команды и ручные
сценарии описаны в [инструкции](testing.md).

## Окружение и источник

- Windows, Python 3.14.6, Node.js 24.18.0.
- Playwright 1.62.1, установленный Google Chrome 153.0.8010.54, headless.
- Три входных parquet — синтетический демонстрационный набор. SHA-256 совпадают
  с `data/demo_manifest.json`; в интерфейсе явно показан источник.
- Браузер загружал сгенерированный HTML из памяти (`setContent`). Внешние
  запросы были заблокированы. Открытие через `file://` в этом прогоне не
  автоматизировалось; его ручная проверка включена в инструкцию.

## Что исправлено при проверке

- Загрузчик раньше мог молча усечь дробный gid или превратить строку `"False"`
  в `True`. Теперь типы, null и диапазон int64 проверяются до приведения.
- Проверка месяца принимала только полночь 31 июля. Теперь принимается весь
  последний день, используется полуинтервал до 1 августа.
- GID в HTML передаются строками; значения выше 2^53 остаются различимыми.
- Данные не могут закрыть тег script; проверены `</script>`, HTML-символы,
  U+2028/U+2029, неконечные числа, экранирование evidence и полнота CSV.
- Повреждённый или устаревший manifest не ломает расчёт и не выдаёт новые
  данные за проверенный демонабор.
- Очередь и CSV используют одинаковый порядок при равных приоритетах.
- Уточнено требование Python: зафиксированный NetworkX 3.7 требует 3.12+
  и исключает 3.14.1. Прежнее указание «3.11+» в инструкции было неточным.
- Исправлены фокус после выбора узла, удержание Tab в справке, слишком мелкая
  мобильная схема и скрытие SVG при переходе к полной сети. Эти случаи теперь
  покрыты тестами или визуальной проверкой снимков.

## Must-have и ограничения задания

Пункты подтверждены для имеющегося демонстрационного набора:

1. Один запуск создаёт все три CSV без ручных промежуточных шагов, менее 5 минут.
2. Каждый из 2 248 узлов имеет роль, role_score и непустое объяснение.
3. Правила и пороги остаются явными в README; карточка раскрывает метрики
   и объяснение, скоры не представлены вероятностями нарушения.
4. Кластеры не пересекают несвязные компоненты; размеры, seed и суммы
   внутренних рёбер сверены с исходными таблицами.
5. Топ-лист содержит 30 обоснованных позиций; интерфейс показывает направления,
   роли и кластеры и находит произвольный gid.

Ограничения раздела 7 `AGENT.md`:

- Нет списков gid с предписанным аналитическим результатом: фильтры,
  приоритеты и карточки используют рассчитанные данные.
- Нет чёрного ящика: правила и формула приоритета сохранены и объясняются.
- Нет внешнего обогащения и выдуманных атрибутов клиентов.
- Для расчёта и просмотра не нужны облако, GPU, платные сервисы или сеть.
  Интернет нужен лишь для первоначальной установки зависимостей.
- Интерфейс использует только обезличенные gid, структуру, суммы и даты.
  Сам HTML содержит данные, поэтому его нельзя считать безопасным для
  публичного размещения с реальной финансовой выгрузкой.
- Роли и выводы обозначены гипотезами, не обвинениями; граница обхода
  показана как ограничение наблюдений.

## Что этим прогоном не подтверждено

Нет оригинальных parquet и ground truth: точность ролей на реальных данных
не измерялась. Противоречие про 19 отсутствующих в рёбрах seed и 16 компонент
сохранено в документации, а не скрыто подгонкой результатов.

Не проверены Firefox/Safari, экранные дикторы, реальный browser zoom 200%,
миллион узлов и все возможные действия пользователя. Проверка узких viewport
не заменяет ручную проверку масштаба. Это не сертификат WCAG и не полный
аудит безопасности: Python-пакеты проверены на согласованность, но свежая
база CVE для всего Python-окружения в этом прогоне не сканировалась.

Вывод: расчёт и перечисленные пользовательские сценарии работают на текущем
наборе; оставшиеся границы проверки явно указаны для следующей приёмки.
