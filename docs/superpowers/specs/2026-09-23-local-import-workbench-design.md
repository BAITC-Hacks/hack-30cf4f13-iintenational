# Локальное приложение «Потоки»: мастер импорта

Основание: пользователь согласовал локальное приложение перед универсальным CLI,
оба способа входа (одна таблица переводов и отдельные таблицы) и разрешил
приступить к реализации 23 сентября 2026. Этот документ фиксирует данный объём.

## Результат первой версии

Локальная страница принимает CSV, TSV, XLSX, JSON, JSONL и Parquet. Пользователь
выбирает назначение таблиц, сопоставляет поля, просматривает ошибки, запускает
анализ и открывает сохранённый результат. Существующий offline-экран графа
используется повторно. Сервер слушает только 127.0.0.1; многопользовательский
доступ, облако, базы данных и внешние API не входят в эту версию.

Начальный экран содержит новый импорт и историю. Шаги мастера: файлы → поля
и условия наблюдения → проверка → запуск. Переход назад сохраняет выбор, но
любое изменение входа отменяет прежнюю успешную проверку. Ошибки указывают
таблицу, строку и поле, не скрываются за общим сообщением об отказе.

## Два независимых контракта

**HackAlem:** все прежние контрольные числа, исходные правила и схемы CSV
остаются обязательными. Существующий `run.ps1` не меняет поведение. Для запуска
через мастер требуются nodes, edges и transactions; переименование и чтение
другого табличного формата не ослабляет проверку содержимого.

**Пользовательский:** принимает одну таблицу транзакций либо edges с необязательными
nodes и transactions. Узлы и агрегированные рёбра можно получить из транзакций.
Из рёбер нельзя восстановить отсутствующие даты или отдельные транзакции.
Если переданы и рёбра, и транзакции, их суммы и число операций должны совпасть.
Изолированные узлы из явной таблицы nodes сохраняются.

Общие проверки: уникальность идентификаторов, ссылки, конечные положительные
суммы, согласованность агрегатов, понятный отказ на пустом наборе и петлях.
Одинаковые транзакции не удаляются автоматически: совпадение полей не является
доказательством дубля. Строковые ID и ведущие нули сохраняются. Личные атрибуты
не входят в контракт и не используются для расчёта или объяснений.

## Форматы и нормализация

CSV/TSV: явные разделитель и кодировка (UTF-8/UTF-8 BOM или CP1251).
XLSX: выбор листа, чтение без исполнения формул. В реализации проверка усилена:
формулы отклоняются на всём выбранном листе, а не только в сопоставленных полях;
старый XLS, XLSM, архивы и исполняемые форматы не принимаются.
JSON — массив плоских объектов; JSONL — один плоский объект на строку.
Parquet читается ограниченными порциями после проверки метаданных.

Сопоставление колонок подтверждает пользователь. Совпадения стандартных названий
могут быть предложены, но направление перевода и единицы суммы не угадываются.
Суммы нормализуются через Decimal в целые минимальные единицы, без округления
неподходящей точности. Для одного анализа явно выбирается одна валюта и число
десятичных знаков 0–6; смешанные валюты отклоняются. Конвертации валют нет.
Формат даты задаётся явно; пустое необязательное поле остаётся неизвестным.

## Полнота наблюдений и аналитика

Отсутствие seed/depth не превращается в false/0. Максимальная наблюдаемая глубина
сама по себе не объявляется границей. По умолчанию условия наблюдения неизвестны:
правила, требующие надёжной интерпретации входа/выхода, не используются для
назначения transit/terminal, а ограничение объясняется. Пользователь может явно
указать исходящий обход и его предельную глубину, если это известно об источнике.

Повторно используются графовые метрики и Louvain по компонентам. Роли остаются
объяснимыми гипотезами, а скор — не вероятностью нарушения. Разрешённый реестр
стадий сообщает «выполнено / неприменимо» с причиной. Загружаемые данные не могут
содержать Python-код, выражения правил или пути к подключаемым модулям.
Параметр top-N задаётся в мастере, в пользовательском режиме ограничивается
фактическим числом узлов. Пороги и версия правил сохраняются с результатом.

## Хранение и безопасность

Данные приложения находятся в исключённом из Git `workbench_data/`, не в data/
или outputs/. Имена на диске назначает сервер, клиент не задаёт пути. Отдельный
идентификатор запуска связывает исходные хеши, настройки, отчёт, CSV и HTML.
Неуспешный запуск не объявляет частичные файлы готовым результатом. История
восстанавливается после перезапуска; незавершённый запуск помечается прерванным.

Начальные пределы: 20 MiB на файл, 100 000 строк на таблицу, 10 000 узлов,
50 000 рёбер, один расчёт одновременно. Превышение означает понятный отказ,
не скрытое усечение. Эти пределы — границы первой локальной версии, не обещание
поддержки миллиона узлов. Ограничиваются также распакованный размер XLSX,
число колонок, длина текстовых значений и суммарное хранилище загрузок.

API проверяет Host/Origin и случайный токен сессии; CORS не открывается.
Токен не включается в URL. Встроенные файлы UI выдаются по явному списку;
произвольное чтение файлов и доступ к соседним каталогам отсутствуют.
Вывод текста экранируется; CSV защищаются от формул из строковых идентификаторов.
Локальные файлы не шифруются: доступ к учётной записи ОС означает доступ к ним.

## Архитектура и следующий этап

- `workbench/importing.py` — адаптеры файлов, предпросмотр и нормализация.
- `workbench/models.py` — контракты входа, пределов и ошибок.
- `workbench/analysis.py` — профили, оркестрация и воспроизводимые артефакты.
- `workbench/server.py` — локальный HTTP, загрузки и последовательные задания.
- `workbench/web/` — мастер и история, без внешних ресурсов.
- `aml_graph/visualization.py`, `web/` — общий просмотр результата.
- `run_app.py`, `run_app.ps1` — запуск приложения.

Следующий этап CLI будет вызывать тот же `run_analysis`, передавая конфигурацию
и источники из файла. Универсальный batch CLI в текущую поставку не входит.
Временные паттерны, циклы, внешние интеграции и новые аналитические роли также
остаются отдельными последующими расширениями.

## Приёмка

1. Прежние 40 Python-тестов и 17 сценариев offline-экрана не регрессируют.
2. Одна и та же небольшая сеть, импортированная из шести форматов, даёт
   одинаковые узлы, суммы и роли; строковые ID и денежная точность сохранены.
3. Один файл транзакций и согласованный набор таблиц дают сопоставимые результаты.
4. Неизвестные seed/depth, граница другого колена, маленький и несвязный граф
   не трактуются как исходные условия HackAlem.
5. Мастер проходит путь загрузки, mapping, ошибки, расчёта и повторного открытия
   истории. Перезагрузка страницы не теряет завершённый результат.
6. Проверены недопустимые форматы, повреждённые данные, лимиты, traversal,
   запросы без токена, чужой Origin и текстовые/CSV-инъекции.
7. README и инструкция включают запуск, поддерживаемые поля, ограничения,
   очистку локальных данных и фактический протокол тестирования.
