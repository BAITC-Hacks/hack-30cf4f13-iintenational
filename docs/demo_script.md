# Пятиминутное живое демо

Это подготовленный сценарий, а не отчёт о проведённом выступлении. Он рассчитан
на текущий **синтетический** набор; оригинальные данные HackAlem не предоставлены.
Подготовка зависимостей и установка браузера не входят в пять минут.

## До выступления

1. Выполнить установку и проверки из [README](../README.md#тесты), убедиться,
   что запуск завершается без ошибок. Генератор данных для показа не запускать:
   он перезаписывает Parquet и не является стадией анализа.
2. Подготовить терминал в корне репозитория, локальный `outputs/graph_view.html`,
   [диаграмму](architecture.svg) и раздел [правил ролей](../README.md#правила-ролей-и-пороги).
3. После пробного расчёта выбрать два gid из фактически полученного top и один
   граничный узел. Эта команда только читает результаты и исходную глубину:

   ```powershell
   .\.venv\Scripts\python.exe -X utf8 -c "import pandas as pd; top=pd.read_csv('outputs/top_nodes.csv'); nodes=pd.read_parquet('data/nodes.parquet'); roles=pd.read_csv('outputs/nodes_roles.csv'); boundary=nodes[nodes.depth.eq(4)].merge(roles,on='gid').sort_values('gid').head(1); print(top.head(2)[['rank','gid','role','priority_score','why']].to_string(index=False)); print(boundary[['gid','depth','role','evidence']].to_string(index=False))"
   ```

   Не зашивать эти gid в алгоритм и не назначать им роли вручную. После живого
   запуска сверить выбор со свежим `top_nodes.csv`. При изменении данных брать
   новые фактические значения; если ожидаемый узел отсутствует или проверка
   не проходит, показать расхождение и остановиться, не выдавая старый результат
   за новый. Произвольный gid жюри может заменить второй узел из top.

## Сценарий: 0:00–5:00

### 0:00–0:25 — задача и источник

«Система помогает выбрать узлы транзакционной сети для проверки и объясняет
каждый сигнал через наблюдаемые метрики. Сейчас показан детерминированный
синтетический набор, а не оригинальные данные соревнования. Роли — гипотезы,
не обвинения». Показать диаграмму: данные → метрики → роли → интерфейс.

### 0:25–0:55 — живой запуск

В терминале выполнить одну команду:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Показать фактическое время и контрольные числа из вывода: на включённой
синтетике ожидаются 2 248 узлов, 3 119 рёбер, 4 840 транзакций, 16 компонент.
Открыть только что обновлённый локальный `outputs/graph_view.html` и указать
маркировку демонстрационного источника. При ошибке не продолжать по старому HTML.

### 0:55–2:35 — два узла из рассчитанного top

По очереди найти выбранные gid через поиск. Для каждого показать:

- направление входящих/исходящих рёбер и суммы в «Таблице связей»;
- роль, её фактические метрики и сработавший порог из README;
- `cluster_id`, `role_score` и причины приоритета из `why` в свежем CSV.

Если оба узла имеют одну роль, это не ошибка и не повод менять алгоритм:
сравнить силу правила, компонентный процентиль центральности и глобальный
процентиль оборота. Объяснить, что процентиль — относительный ранг, а не
вероятность виновности. При равных оценках показать документированный
порядок сортировки, а не придумывать различие в поведении узлов.

### 2:35–3:15 — третий узел, граница наблюдения

Найти выбранный `depth=4` gid. Сопоставить исходную глубину, отсутствие исходящих
и объяснение роли. В текущей синтетике все 444 узла границы — `peripheral`:
`out=0` не делает их `terminal`. В общем случае входящие связи могут дать
`consolidator` по структурному порогу; запрещён именно вывод о терминальности
из искусственно нулевого выхода.

### 3:15–4:10 — сеть и готовые результаты

Открыть «Вся сеть», переключить цвет с роли на кластер. Показать несвязные
компоненты и пояснить: сообщества ищутся отдельно внутри каждой компоненты.
Вернуться к таблице связей — она содержит всех контрагентов выбранного узла,
в том числе отсутствующих в компактной схеме. Показать три CSV в `outputs/`:
на текущей синтетике 2 248 строк ролей, 89 кластеров и 30 приоритетных узлов.
Это результаты расчёта, а не размеченная истина.

### 4:10–5:00 — ограничения и следующий шаг

Назвать ограничения наблюдений: исходящие внутри банка за июль 2026, порог
5 000 KZT, неполные входящие seed, обрыв на четвёртом колене. Сказать, что
ground truth отсутствует и качество ролей на оригинальных данных не измерено.

Открыть [таблицу расхождений](../data/README.md#расхождения-с-описанием-исходного-набора):
869 узлов с `sum_out > sum_in` вместо описанных 354; изолированных seed — 0
вместо 19, recipient-only — 31 вместо 12. Число 352 вне крупнейшей компоненты
противоречит `2248 − 1877 = 371`. Генератор и правила к этим числам не подгоняются.
Завершить следующим шагом: получить оригинальные Parquet, уточнить противоречия
с организаторами и повторить проверку без подмены источника.
