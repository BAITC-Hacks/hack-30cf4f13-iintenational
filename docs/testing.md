# Проверка проекта перед демонстрацией

Эта инструкция описывает повторяемую проверку расчёта, CSV и интерфейса. Она не
является протоколом уже выполненных проверок. Фактический результат, время,
версию Python/браузера и обнаруженные отклонения записывайте при каждом прогоне.

Текущие `data/*.parquet` — **синтетические демонстрационные данные**, а не
оригинальный набор HackAlem. Успешные проверки подтверждают работу программы на
этом наборе; они не подтверждают правильность гипотез о реальных клиентах.
Размеченных ролей нет, поэтому accuracy здесь не измеряется.

## 1. Подготовка окружения

Откройте PowerShell в корне репозитория. Требуется Python 3.12+ (кроме 3.14.1,
исключённой метаданными NetworkX 3.7); для проверки
JavaScript — Node.js 20+. GPU, облако и платные сервисы не нужны. Интернет требуется
при первоначальной установке зависимостей.

```powershell
python --version
node --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Если `.venv` уже подготовлено, повторять его создание не требуется. Все команды
ниже выполняются из корня проекта. На Linux/macOS используйте
`.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

Проверьте наличие `data/nodes.parquet`, `data/edges.parquet` и
`data/transactions.parquet`. Пайплайн читает их напрямую. Генератор
`scripts/generate_demo_data.py` предназначен только для восстановления демо;
не запускайте его поверх оригинальных входных файлов.

## 2. Полный запуск одной командой

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

На других ОС эквивалентен запуск `.venv/bin/python run_pipeline.py`.
Успешный запуск завершается кодом `0`, печатает отчёты стадий и создаёт:

- `outputs/nodes_roles.csv`;
- `outputs/clusters.csv`;
- `outputs/top_nodes.csv`;
- `outputs/graph_view.html`;
- `outputs/run_report.json`.

Команда обновляет содержимое `outputs/`. Если нужно сохранить предыдущий
результат, заранее скопируйте этот каталог в отдельную папку.

Проверьте код завершения сразу после запуска:

```powershell
$LASTEXITCODE
Get-Content .\outputs\run_report.json
```

В `run_report.json` поле `total_seconds` должно быть меньше `300`. Для замера
полного времени процесса вместе со стартом Python используйте:

```powershell
Measure-Command { powershell -ExecutionPolicy Bypass -File .\run.ps1 }
```

Время установки библиотек не входит в ограничение пяти минут. Сравнивайте
результаты на одном компьютере и указывайте его конфигурацию в протоколе.

## 3. Контрольные числа и ограничения данных

Сопоставьте `input` в отчёте с таблицей. При расхождении сначала проверяйте путь
к данным и причину ошибки; не меняйте числа, роли или исходные файлы ради
успешного результата.

| Проверка | Ожидание для текущего демо |
|---|---:|
| Узлы / направленные рёбра / транзакции | 2 248 / 3 119 / 4 840 |
| Seed | 81 |
| Сумма рёбер и транзакций | 365 890 012 KZT |
| Число узлов по `depth` 0 / 1 / 2 / 3 / 4 | 81 / 472 / 462 / 789 / 444 |
| Слабосвязные компоненты | 16 |
| Две крупнейшие компоненты | 1 877 и 270 узлов |
| Остальные 14 компонент | каждая от 2 до 17 узлов |
| Узлы `depth=4` без исходящих | 444 |
| Seed без исходящих | 31 |
| Seed полностью вне рёбер / только получатели | 0 / 31 |

В ТЗ есть несовместимые утверждения: 19 seed полностью отсутствуют в рёбрах, но
во всей сети только 16 компонент. Каждый отсутствующий узел дал бы отдельную
компоненту. Демо сохраняет 16 компонент и 31 seed без исходящих, при этом все
31 seed присутствуют как получатели. Это известное расхождение описано в
[`data/README.md`](../data/README.md); его нельзя считать выполнением обоих
условий оригинального ТЗ. При появлении оригинальных данных потребуется сверка
с организаторами.

Число Louvain-кластеров и распределение ролей являются результатами алгоритма.
Для одного входа и зафиксированных версий они должны воспроизводиться, но их
нельзя подгонять под заранее выбранный ответ. Отчёт `candidates` должен содержать
кандидатов с 8–24 плательщиками и 60–116 получателями; число pass-through
профилей должно быть не меньше 72. Кластеров с несколькими seed должно быть
не меньше восьми.

## 4. Автоматические проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node scripts/check_graph_view.js
```

Обе команды должны завершиться с кодом `0`; Python выводит `OK`. Наличие файла
`graph_view.html` и корректный синтаксис JavaScript сами по себе не доказывают,
что кнопки и поиск работают в браузере: для этого нужны проверки из следующих
разделов.

Acceptance-тесты запускают пайплайн в отдельном временном каталоге, поэтому для
проверки с нуля не требуется удалять `outputs/`. Они проверяют заполненность
ролей, согласованность кластеров, топ-лист, ограничения на время и обработку
четвёртого колена. Подробный состав проверок виден в выводе `unittest`.

### Функциональная проверка в браузере

После успешного пересчёта `outputs/graph_view.html` установите отдельную
зависимость для разработки и запустите сценарий:

```powershell
npm ci
npm run test:ui
```

`npm ci` устанавливает точные версии из `package-lock.json`. Если на Windows
команда `npm` выдаёт `MODULE_NOT_FOUND` для `npm-cli.js` или ошибка относится к
оболочке `npm.ps1`, используйте `npm.cmd ci` и `npm.cmd run test:ui`.
Не требуется менять глобальные настройки PowerShell или npm.

Сценарий использует Playwright, зафиксированный в `package.json`. На Windows
он автоматически находит Google Chrome в стандартных папках установки. Если
Chrome там отсутствует, укажите путь к установленному браузеру Chromium:

```powershell
$env:BROWSER_PATH = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
npm run test:ui
```

Альтернативно установите управляемый Playwright Chromium командой
`npx playwright install chromium` и запускайте тест без `BROWSER_PATH`.
Скачивание браузера требует интернет; сам функциональный прогон работает
локально. Эти зависимости не нужны для расчёта Python и обычного открытия HTML.

`scripts/test_ui.js` загружает готовый HTML в память браузера и блокирует
сетевые запросы. Он проверяет сводные числа, начальный приоритетный узел,
точный поиск, несуществующий и некорректный `gid`, три фильтра и их сброс,
пустую выборку, пагинацию очереди и всех связей, переход к соседу, смену
области/раскраски графа, масштабирование, справку, возврат и удержание фокуса,
выбор узлов через Enter и предупреждение о границе обхода. Скачанные
CSV сверяются с исходными файлами и встроенными в HTML данными. На ширинах
1440, 390, 320, 640 и 768 пикселей проверяется отсутствие горизонтального выхода страницы
за экран. Необработанные исключения, ошибки консоли и попытки сетевых запросов
завершают проверку ошибкой.

Результаты сохраняются в `artifacts/`:

- `ui-test-report.json` — фактический статус каждого выполненного сценария;
- `ui-desktop.png`, `ui-mobile.png`, `ui-network.png`, `ui-table.png` — снимки интерфейса;
- `downloads/` — три скачанных CSV;
- `ui-failure.png` — состояние страницы при ошибке, если браузер успел открыться.

Успешный результат — строки `PASS`, код завершения `0` и `status: "passed"`
в JSON. Скрипт останавливается при первой ошибке; последующие сценарии в этом
прогоне не проверены. После устранения причины повторите полный прогон.
Отчёт также сохраняет версии браузера и Node.js. Старые снимки могут остаться от предыдущего запуска: ориентируйтесь на время
`startedAt`/`finishedAt` в отчёте. Автоматический сценарий не заменяет ручную
оценку читаемости, клавиатурной навигации и масштаба 200%.

Отдельная проверка границы обхода на сохранённой выгрузке:

```powershell
.\.venv\Scripts\python.exe -c "import pandas as pd; n=pd.read_parquet('data/nodes.parquet'); e=pd.read_parquet('data/edges.parquet'); r=pd.read_csv('outputs/nodes_roles.csv'); b=n.loc[n.depth.eq(4)].merge(r,on='gid',validate='one_to_one'); assert len(b)==444; assert not b.gid.isin(e.src).any(); assert not b.role.eq('terminal').any(); print('OK: 444 boundary nodes; no outgoing edges; no terminal role')"
```

Ожидание: ровно 444 узла, ни одного исходящего ребра, ни одной роли `terminal`
на границе. В карточках этих узлов должно быть объяснение ограничения обхода.
Это проверка корректности интерпретации отсутствующих наблюдений.

Если меняете валидацию, проверяйте отклонение повреждённого входа только на
временных копиях: отсутствующая колонка, пустое обязательное значение, дробный
`gid`, неизвестный конец ребра, дубли `gid`/пар, расхождение агрегации, дата вне
июля 2026, сумма ниже 5 000 KZT. Ожидается понятная ошибка и ненулевой код
завершения. Сохранившиеся от предыдущего запуска CSV не являются результатом
такого неуспешного запуска.

## 5. Проверка CSV

Откройте файлы как UTF-8 или импортируйте их с правильной кодировкой. Для
автоматической сверки предпочтительнее Python/pandas; таблицы могут изменить
формат длинных идентификаторов при открытии в офисном редакторе.

| Файл | Что проверить |
|---|---|
| `nodes_roles.csv` | Ровно 2 248 уникальных `gid`; колонки `gid, role, role_score, cluster_id, priority_score, evidence`; все поля заполнены; оба score в диапазоне 0–1; `evidence` не длиннее 200 символов |
| `clusters.csv` | Уникальный `cluster_id`; колонки `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`; множество кластеров совпадает с `nodes_roles.csv`; сумма `n_nodes` равна 2 248 |
| `top_nodes.csv` | Не менее 20 узлов (текущая конфигурация — 30); колонки `rank, gid, role, priority_score, why`; ранги без пропусков с 1; приоритет не возрастает вниз; `why` объясняет факторы приоритета |

Допустимый словарь ролей: `coordinator`, `consolidator`, `distributor`,
`transit`, `terminal`, `peripheral`. Для трёх произвольных `gid` найдите строку
в CSV, откройте карточку и сопоставьте метрики с правилами в README. Соблюдайте
порядок применения правил: один узел может иметь признаки нескольких ролей.

## 6. Ручная проверка интерфейса

Откройте `outputs/graph_view.html` в современном Chrome, Edge или Firefox.
Экран автономный; сервер для обычной работы не нужен. Для каждого сценария
фиксируйте «пройдено», «ошибка» или «не проверено», а не только факт открытия
страницы.

| Сценарий | Действия и ожидаемый результат |
|---|---|
| Первое открытие | Видны очередь проверки, текущий выбранный узел и понятные подписи. Числа согласованы с CSV. Пометка о демонстрационных данных и гипотезах доступна |
| Выбор из очереди | Выберите несколько строк. Выделение, карточка, схема и список связей относятся к одному `gid`; метрики и объяснение совпадают с CSV |
| Точный поиск | Возьмите любой `gid` из `nodes_roles.csv`, введите полностью и нажмите Enter. Открывается именно этот узел, включая находящийся вне топ-30 |
| Некорректный поиск | Введите пустую строку, буквы и заведомо отсутствующий `gid`. Интерфейс сообщает об ошибке/отсутствии результата, не показывает случайный другой узел и остаётся работоспособным |
| Фильтры | Поочерёдно примените роль, компоненту и кластер, затем сочетание фильтров. Все строки очереди соответствуют выбору; счётчик согласован. Сброс возвращает полный список |
| Пустая выборка | Подберите несовместимые фильтры. Появляется понятное пустое состояние с возможностью сброса; прежние результаты не выдаются за найденные |
| Локальная схема | В режиме «Связи узла» видны выбранный узел и его соседи. На большом экране входящие слева, исходящие справа; на узком — сверху и снизу. Показаны до 12 крупнейших связей каждого направления, на узком экране до четырёх. Подпись показывает фактическое число видимых связей. Сверьте направление двух переводов с `src → dst` в данных |
| Вся сеть | Переключитесь на «Вся сеть». Видны разные компоненты; смена выбранного узла сохраняет понятный контекст. Возврат к локальному режиму работает |
| Раскраска | Переключите роли/кластеры. Цвета и легенда соответствуют выбранному режиму, а текст роли и номера кластера остаётся доступным без различения цветов |
| Масштаб и положение | Используйте увеличение, уменьшение, перенос и вписывание схемы. После сильного приближения «вписать» возвращает доступный вид |
| Полный список связей | Для узла с большим числом соседей откройте табличный список. Пройдите страницы, проверьте направления, суммы и число переводов по входным данным. Одна связь не теряется и не повторяется из-за пагинации |
| Переход к соседу | Выберите соседний `gid` из таблицы. Карточка и схема обновляются; поиск нового узла показывает тот же результат |
| Граница обхода | Откройте узел с `depth=4`. Интерфейс объясняет неполноту наблюдений, не объявляет его настоящим конечным получателем только из-за отсутствия выхода |
| Скачивание | Скачайте все три CSV. Имена, заголовки, число строк, `gid` и значения совпадают с файлами в `outputs/`; кириллица читается |
| Инструкция | Откройте встроенную помощь, прочитайте порядок работы и ограничения. Закройте её кнопкой и Escape, продолжите поиск |
| Работа без сети | Отключите сеть в инструментах разработчика и перезагрузите страницу. Схема, поиск, фильтры, помощь и скачивание остаются доступны |

В консоли браузера не должно быть необработанных исключений. В Network после
открытия автономного файла не должно быть запросов к внешним сервисам, шрифтам
или аналитике. Не считать отсутствие запросов проверкой всех возможных
уязвимостей: это проверка заявленной автономности экрана.

## 7. Клавиатура, масштабирование и небольшой экран

1. Пройдите основные действия только клавиатурой: Tab/Shift+Tab, Enter/Space,
   клавиши управления выпадающими списками. Фокус должен быть видим, порядок
   перехода — понятен. Найдите узел, примените и сбросьте фильтр, выберите
   соседа через таблицу, скачайте CSV.
2. Откройте окно инструкции клавиатурой. Фокус остаётся в открытом окне; Escape
   закрывает его и возвращает фокус к вызвавшей кнопке.
3. При масштабе браузера 200% проверьте поиск, фильтры, карточку и пагинацию.
   Текст и кнопки не должны перекрывать друг друга. Таблица может иметь
   собственную горизонтальную прокрутку; это не должно мешать чтению страницы.
4. В режиме эмуляции проверьте ширины 390 и 768 CSS-пикселей, затем обычный
   рабочий экран 1440 пикселей. Все важные действия доступны, подписи читаются,
   страница не уходит за границы экрана. Повторите поиск и выбор соседа.
5. Проверьте уменьшение движения в системных настройках и достаточность
   текстовых подписей без опоры только на цвет. Для невизуальной работы
   проверяйте доступность карточки и таблицы связей; Canvas сам по себе не
   заменяет текстовый способ навигации.

## 8. Приёмка по заданию

| Обязательный пункт | Подтверждение для протокола |
|---|---|
| Один запуск меньше пяти минут | Команда, код завершения, время и пять созданных артефактов |
| Роль и объяснение каждого узла | Проверки CSV: 2 248 строк, допустимые роли, score, заполненные evidence |
| Явные правила | Разбор трёх произвольных узлов по README и карточке; отдельная проверка `depth=4` |
| Кластеризация несвязной сети | 16 компонент, согласованные cluster_id, суммы размеров и гипотезы |
| Топ-лист и схема | Не менее 20 позиций с why, работающий поиск произвольного gid, направления потоков |

При финальном просмотре кода и текстов проверьте ограничения раздела 7
`AGENT.md`: результат вычисляется из метрик без списков «правильных gid»;
правила объяснимы; внешнее обогащение и отсутствующие клиентские атрибуты не
используются; запуск локальный без GPU и платных сервисов; данные обезличены;
тексты `evidence`, `why`, `hypothesis` и интерфейс формулируют гипотезы.

```powershell
npm.cmd run test:workbench
```

Для теста мастера используется тот же `BROWSER_PATH` или установленный Chrome,
что и для `test:ui`. Python берётся из проектного `.venv`. Тест сам запускает
локальный сервер на свободном порту, создаёт отдельное временное хранилище и
останавливает свой процесс. Пользовательский `workbench_data/` не изменяется.
Внешние сетевые запросы не нужны и не допускаются. Проверяйте код завершения,
все строки `PASS` и свежий JSON-отчёт в `artifacts/`.

Модули Python можно проверять отдельно:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_importing -v
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_workbench_analysis -v
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_workbench_server -v
```

| Область | Ожидаемое поведение |
|---|---|
| Адаптеры | Одна и та же сеть в CSV/TSV/XLSX/JSON/JSONL/Parquet даёт одинаковые результаты; ведущие нули и точность денег сохраняются |
| Проверки импорта | Неверный mapping, пустые/дробные ID, лишняя точность суммы, смешанные валюты, петли, несовпадающие агрегаты и превышение лимитов отклоняются без усечения |
| Неизвестные факты | Нет автоматического seed/depth; неизвестное количество операций не превращается в 0; transit/terminal отключены без нужного контекста |
| Граница обхода | Пользовательская граница 2 или 5 работает по заданным условиям; глубина 4 сама по себе не является границей |
| Совместимость | Три CSV профиля HackAlem побайтово совпадают с прежним `run_pipeline.py` на тех же данных |
| HTTP и хранение | Чужие Host/Origin, отсутствие токена, traversal, неверные длины/форматы запросов, слишком большие загрузки отклоняются; незавершённые расчёты не выдают готовые файлы |
| Восстановление | Второй сервер не открывает то же хранилище; после рестарта история остаётся, прерванные расчёты помечены |
| Безопасный вывод | HTML-подобные ID — текст, не код; формульные ID защищены в CSV, канонические значения сохранены в JSON и поиске |

### Ручная приёмка мастера

1. Запустите `powershell -ExecutionPolicy Bypass -File .\run_app.ps1` и откройте
   адрес из терминала. Загрузите `examples/workbench/transactions.csv`.
2. Проверьте mapping; выберите USD, 2 десятичных знака, неизвестную полноту.
   Ожидайте 3 узла, 2 связи, 2 перевода, 1 компоненту и оборот 1250.25 USD.
3. Перед расчётом уберите поле отправителя: проверка должна показать ошибку,
   не запускать анализ и позволить исправить mapping.
4. Запустите корректный набор. Найдите `001` в графе: ведущие нули сохранены;
   seed/глубина неизвестны. Сверьте суммы и направление в таблице связей.
5. Скачайте все шесть файлов. CSV и `result.json` относятся к выбранному
   расчёту; `graph_view.html` работает отдельно от сервера, без интернета.
6. Перезагрузите вкладку, откройте результат в истории. Остановите сервер,
   запустите с тем же каталогом и повторите проверку сохранённого расчёта.
7. Создайте новый анализ из всех трёх файлов `examples/workbench/` (кроме
   README). Ожидайте 4 узла и 2 компоненты: `ISOLATED` не потерян.
8. Пройдите мастер только клавиатурой, затем на ширине 375 px и с масштабом
   200%. Фокус, подписи, ошибки и кнопки должны оставаться доступными; большие
   таблицы могут прокручиваться внутри своего контейнера.
9. Выберите строгий профиль HackAlem для маленького примера: получите отказ
   с объяснением, а не подгонку размеров. Для проверки строгого успеха загрузите
   три `.parquet` из `data/`, сопоставьте `sum_kzt` → сумма и остальные поля.

Для настоящих финансовых файлов сначала проверьте происхождение, обезличенность
и права доступа к локальному хранилищу. Тесты на синтетике не доказывают качество
ролей на новых данных, отсутствие всех уязвимостей или работу на миллионе узлов.

Не отмечайте пункт выполненным, если его только просмотрели в исходном коде.
При ошибке приложите точную команду или последовательность действий, `gid`,
текущие фильтры и сообщение ошибки. Оригинальные финансовые данные не следует
прикладывать к публичным отчётам об ошибках.
