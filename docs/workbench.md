# «Потоки»: локальный мастер импорта

Мастер принимает собственные обезличенные таблицы, проверяет их и запускает
объяснимый анализ без облака. Один файл переводов и набор связанных таблиц
используют одно аналитическое ядро. Старый `run.ps1` сохраняет строгий контракт
HackAlem; мастер не заменяет и не ослабляет его.

## Запуск

После установки зависимостей из [README](../README.md):

```powershell
powershell -ExecutionPolicy Bypass -File .\run_app.ps1
```

Откройте показанный в терминале адрес: по умолчанию
`http://127.0.0.1:8765`. Терминал должен оставаться открытым. Для остановки
нажмите `Ctrl+C`; затем закройте вкладку. Браузер автоматически не запускается.

Если порт занят или нужен отдельный каталог данных:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_app.ps1 -Port 8766 -DataDir "C:\Data\Potoki"
```

`-DataDir` лучше задавать абсолютным путём. Скрипт использует Python из проектного
`.venv` и сам переходит в корень проекта. Эквивалент без PowerShell, из корня:

```powershell
.\.venv\Scripts\python.exe -X utf8 run_app.py --port 8765
```

Node.js и Playwright нужны только для браузерных тестов, не для работы мастера.
После установки Python-зависимостей расчёт и просмотр не требуют интернета.

## Порядок работы

1. Добавьте от одного до трёх файлов. Выберите назначение каждой таблицы:
   `transactions`, `edges` или `nodes`. Каждое назначение используется один раз.
2. Проверьте предпросмотр, разделитель, кодировку или лист Excel. Сопоставьте
   исходные колонки с полями системы. Автоматические предложения имён нужно
   проверить: направление перевода и единицы суммы система не угадывает.
3. Выберите профиль, валюту и точность, размер топ-листа, известные условия
   наблюдения. Если способ сбора неизвестен, оставьте полноту неизвестной.
4. Выполните проверку. Исправьте ошибки и повторите её; изменение файлов,
   сопоставления или настроек отменяет предыдущую успешную проверку.
5. Запустите анализ. После завершения откройте граф или скачайте CSV/отчёт.
   Результат останется в истории после перезагрузки страницы и сервера.

Ошибка указывает таблицу, поле и, когда возможно, номер строки данных с единицы
**без строки заголовков**. API возвращает до 100 ошибок; мастер показывает первые
12, после исправления повторите проверку. Значения не удаляются,
не округляются и не исправляются молча. Совпадающие транзакции сохраняются с
предупреждением: одинаковые поля ещё не доказывают дубль.

## Поддерживаемые форматы

| Формат | Контракт |
|---|---|
| CSV | Заголовок в первой строке; разделитель `,`, `;`, табуляция или `|`; UTF-8, UTF-8 BOM либо CP1251 |
| TSV | Те же правила; по умолчанию разделитель — табуляция |
| XLSX | Один выбранный лист, заголовок в первой строке; по умолчанию первый лист. Формулы, макросы и зашифрованные книги отклоняются |
| JSON | Массив плоских объектов; названия свойств — колонки |
| JSONL | Один плоский объект на строку; пустые строки пропускаются |
| Parquet | Плоская таблица; предварительная проверка метаданных и чтение пакетами |

XLS, XLSM, ZIP и произвольные исполняемые форматы не поддерживаются. Вложенные
JSON-объекты, массивы внутри ячеек, повторяющиеся имена колонок и NaN/Infinity
отклоняются. Формулы XLSX запрещены на всём выбранном листе: сохраните именно
значения в отдельную книгу. Числа XLSX длиннее 15 цифр неоднозначны и
отклоняются — длинные ID и точные суммы храните текстом.

## Поля и сопоставление

Названия исходных колонок могут быть другими: например, `payer` → `src`,
`receiver` → `dst`, `value` → `amount`. Одна колонка не может одновременно
обозначать несколько полей.

| Таблица | Обязательно в пользовательском профиле | Необязательно |
|---|---|---|
| `transactions` | `src`, `dst`, `amount` | `date`, `currency` |
| `edges` | `src`, `dst`, `amount` | `n_tx`, `depth`, `currency` |
| `nodes` | `gid` | `depth`, `is_seed` |

- `gid`, `src`, `dst` — непрозрачные идентификаторы. Текст `001` остаётся
  `001`, а не числом `1`; допускаются буквенные ID. Дробные ID, пустые значения,
  внешние пробелы и управляющие символы недопустимы. Уже потерянные Excel ведущие нули или
  цифры восстановить невозможно.
- `amount` — положительная сумма в **основных единицах** выбранной валюты.
  `n_tx` — положительное целое число переводов агрегированного ребра.
- `depth` узла — известная минимальная глубина обхода; `depth` ребра — глубина
  получателя. Если обе известны, они должны совпадать.
- `is_seed` — `true/false` либо `1/0`. Пустое значение означает «неизвестно»,
  а не `false`.
- `date` — дата без часового пояса. По умолчанию ISO: `2026-07-01` или
  `2026-07-01T12:30:00`. Для другого порядка задайте явный формат, например
  `%d.%m.%Y`; он должен содержать год, месяц и день. Поддерживаются также
  `%H`, `%M`, `%S`, `%f`. Часовые пояса и неоднозначные числовые даты не угадываются.
- Если сопоставлена `currency`, каждая строка обязана совпадать с выбранной
  валютой. Без этой колонки валюта является явным условием, заданным пользователем.

Дополнительные колонки не используются в метриках и объяснениях, но исходный
файл сохраняется локально и показывается в предпросмотре. Не загружайте ФИО,
ИИН или другие личные атрибуты; заранее оставьте только нужные обезличенные поля.

### Вариант A: один файл переводов

`transactions.csv`, валюта `USD`, точность `2`:

```csv
src,dst,amount,date
001,A-2,1000.00,2026-07-01
A-2,B,250.25,2026-07-02
```

Результат проверки: 3 узла, 2 направленных ребра, 2 транзакции, общий объём
1250.25 USD. Узлы и суммы рёбер выводятся из переводов. Seed и depth неизвестны;
без дополнительного контекста правила `transit`/`terminal` недоступны.

Эквивалентный JSON:

```json
[
  {"src": "001", "dst": "A-2", "amount": "1000.00", "date": "2026-07-01"},
  {"src": "A-2", "dst": "B", "amount": "250.25", "date": "2026-07-02"}
]
```

### Вариант B: отдельные таблицы

К той же таблице переводов можно добавить `edges.csv`:

```csv
src,dst,amount,n_tx
001,A-2,1000.00,1
A-2,B,250.25,1
```

И `nodes.csv` с известным изолированным узлом:

```csv
gid
001
A-2
B
ISOLATED
```

Получатся 4 узла и 2 слабосвязные компоненты. Изолированный узел не теряется.
Если `nodes` передана явно, каждый конец ребра должен в ней присутствовать;
неизвестные ID не добавляются молча. Уникальность `gid` и пар `src,dst`
обязательна; петли `src=dst` не поддерживаются.

Допустимы `edges` без транзакций, с необязательной `nodes`: суммы и структура
доступны, даты и отдельные операции не восстанавливаются. Отсутствующее `n_tx`
остаётся неизвестным. Если переданы и `edges`, и `transactions`, проверяются
совпадение пар, суммы и количество операций. Пропущенное `n_tx` в этом случае
можно точно вычислить из переданных транзакций.

## Два профиля

**Пользовательский (`generic`)** не требует контрольных размеров HackAlem,
конкретного периода, KZT или глубины 4. `top_n` задаётся от 1 до 500;
выгружается не больше фактического количества узлов. Структурные правила и
формула приоритета повторно используют [ядро из README](../README.md#правила-ролей-и-пороги).
Пороговые значения не обучаются и не считаются откалиброванными на новом наборе.

**HackAlem (`hackalem`)** требует все три таблицы и прежние обязательные поля:
`nodes(gid,depth,is_seed)`, `edges(src,dst,amount,n_tx,depth)`,
`transactions(src,dst,amount,date)`. Сопоставьте исходную `sum_kzt` с `amount`.
ID должны представлять int64 без ведущих нулей. Фиксированы KZT, точность 0,
top-30 и исходящий обход до глубины 4. Сохраняются проверки 2248 узлов,
3119 рёбер, 4840 транзакций, 81 seed, июля 2026, контрольных сумм и 16 компонент.
Другой формат файла не ослабляет проверку содержимого. Три CSV имеют прежние
точные схемы и воспроизводятся исходным пайплайном.

### Неизвестная полнота и граница обхода

По умолчанию `coverage=unknown`: отсутствие исходящих не означает терминальный
узел, а отношение сумм не используется для назначения `transit`/`terminal`.
Структурные роли, центральности и кластеризация остаются доступны.
Сам признак seed не доказывает неполноту внешнего входа: при неизвестном способе
наблюдения объяснения прямо называют полноту неизвестной.

Если точно известен исходящий обход, выберите `outward` и его `max_depth`
(целое 0–1000). Для потоковых ролей одновременно требуются известные
`depth < max_depth` и `is_seed=false`. Неизвестное поле не подменяется значением.
Узел на объявленной границе не признаётся терминальным; для границы с `out=0`
приоритет умножается на 0.85. Максимум depth из данных сам по себе не создаёт
границу. Противоречия заданным условиям — например, исходящие с предельной
глубины или seed с ненулевой известной глубиной — отклоняются.

Louvain запускается отдельно в каждой слабосвязной компоненте, включая малые
компоненты и изолированные узлы. Вес — `log(1 + amount_minor)`; поэтому
настройка десятичных знаков входит в условия воспроизводимости. Если seed
неизвестен хотя бы для одного узла кластера, полный `n_seed` этого кластера
неизвестен, а не равен нулю.

Отчёт перечисляет доступность стадий: структурные роли, потоковые роли,
кластеризация, приоритет и seed-контекст. Статусы «доступно/выполнено»,
«ограничено» и «недоступно» сопровождаются причиной. Временной анализ отмечен
недоступным: наличие даты само по себе не означает, что временные паттерны
были рассчитаны.

## Деньги и точность

Один анализ использует одну валюту: трёхбуквенный код в верхнем регистре и
`decimals` от 0 до 6. Конвертации и смешанных валют нет. `amount=12.34` при
`decimals=2` хранится как целое `1234` минимальных единиц. Это не настройка
«вход уже в копейках»: файл с минимальными единицами нужно заранее явно
привести к основным единицам.

Нормализация использует Decimal, без скрытого округления. Лишние значащие знаки,
неположительная сумма или превышение лимита — ошибка. Десятичный разделитель
выбирается `.` либо `,`; разделители тысяч не принимаются. Для десятичной запятой
используйте, например, CSV с `;`.

Общая сумма не превышает `(2^63−1)//2` минимальных единиц: это защищает целый
оборот от переполнения. Денежные значения в JSON/HTML пользовательского режима
сериализуются строками; браузер сохраняет точность и выше `2^53−1`. Центральности
и скоры — вычисляемые вещественные показатели, не денежные остатки.

## Результаты и воспроизводимость

Каждый успешный запуск создаёт отдельные файлы:

- `nodes_roles.csv`: `gid,role,role_score,cluster_id,priority_score,evidence`.
- `clusters.csv` пользовательского режима:
  `cluster_id,n_nodes,n_seed,amount_internal,currency,top_gids,hypothesis`.
  Сумма — точный десятичный текст в основных единицах; `top_gids` — JSON-массив
  исходных строковых ID, чтобы запятые внутри ID не были неоднозначны.
- `top_nodes.csv`: `rank,gid,role,priority_score,why`.
- `graph_view.html`: автономный граф с поиском по исходному ID, схемой потоков,
  ролями, кластерами и таблицей связей.
- `result.json`: канонические ID без CSV-префиксов, роли, известные факты,
  направленные связи, точные суммы; неизвестные значения представлены `null`.
  Поля ребра `amount_minor` и `n_tx` — десятичные строки целых чисел (`n_tx`
  также может быть `null`), `amount` — точная строка суммы в основных единицах.
  Счётчик операций не теряет точность при чтении JSON в JavaScript даже выше
  `2^53−1`; для арифметики используйте целые произвольной точности/BigInt.
- `report.json`: настройки, контрольные числа, доступность стадий, предупреждения,
  версии библиотек и правил, пороги, ограничения и время. Для каждого источника
  сохраняются имя, SHA-256, сопоставление и настройки чтения. Хеш подтверждает
  равенство байтов, не подлинность источника.

### Защита CSV от формул

CSV сохраняются в UTF-8 BOM. В пользовательском режиме для текстового ID,
начинающегося с `=`, `+`, `-`, `@` **или самого апострофа** `'`, экспорт добавляет
один апостроф. Начальные пробелы не скрывают триггер. Экранирование исходного
апострофа сохраняет различия между ID:

| Исходный ID | Значение в CSV |
|---|---|
| `=foo` | `'=foo` |
| `'=foo` | `''=foo` |
| `''=foo` | `'''=foo` |

Для обратного преобразования колонки `gid` пользовательского CSV удалите ровно
один начальный апостроф, если он есть. Каноническое значение в `result.json`,
`top_gids` и поиск в графе остаются исходными; экспортный префикс не становится
новым ID в системе. Строгие числовые ID и CSV HackAlem не меняются.
Политика `apostrophe-prefix-v1` и её триггеры записаны в `report.json`.
Для машинного обмена используйте `result.json`,
а при открытии CSV в редакторе импортируйте ID как текст: ведущие нули могут
быть потеряны самим табличным редактором, несмотря на корректный исходный CSV.

## Хранение и очистка

По умолчанию данные приложения отделены от `data/` и `outputs/`:

```text
workbench_data/
  uploads/                 исходные файлы под серверными ID
  uploads.json             индекс загрузок
  runs/<run_id>/
    state.json             состояние и запрос запуска
    artifacts/             CSV, JSON и graph_view.html
```

Этот каталог исключён из Git. Завершённые результаты доступны после рестарта;
незавершённые отмечаются как прерванные и требуют нового запуска. Частичные
файлы не выдаются как готовый результат. Новый анализ не перезаписывает старый.

Автоматической очистки и шифрования на диске нет. Чтобы очистить всё:

1. Остановите сервер через `Ctrl+C` и убедитесь, что расчёт завершён или прерван.
2. Сохраните нужные результаты отдельно.
3. В проводнике проверьте точный путь к **выбранному каталогу приложения**
   (`workbench_data/` либо вашему `-DataDir`) и переместите только его в корзину.
4. Следующий запуск создаст новое пустое хранилище.

Для удаления одного результата при остановленном сервере можно переместить в
корзину только `runs/<точный run_id>/`. Это не удалит связанные исходные загрузки
и не освободит их квоту. Не редактируйте индекс и `state.json` вручную и не
удаляйте части запущенного задания. При пользовательском `-DataDir` самостоятельно
обеспечьте права ОС и исключение каталога из синхронизации или публикации.

## Пределы первой версии и безопасность

| Ограничение | Значение |
|---|---:|
| Файл | 20 MiB |
| Суммарные сохранённые загрузки | 200 MiB |
| Строк на таблицу | 100 000 |
| Колонок | 128 |
| Символов в текстовой ячейке | 4096 |
| Узлов / направленных рёбер | 10 000 / 50 000 |
| Распакованный XLSX или Parquet | 100 MiB |
| Элементов архива XLSX | 1000 |
| Одновременных расчётов на хранилище | 1 |

Лимиты дают отказ, а не скрытое усечение. Квота 200 MiB относится к загрузкам,
не к суммарному размеру результатов: следите за свободным местом. Предел
10000 узлов — ограничение приёма, не гарантия времени на произвольной топологии.
Пятиминутный контракт относится к объёму HackAlem; миллион узлов здесь не
поддерживается. [План масштабирования](../README.md#масштабирование-до-примерно-1-млн-узлов)
не является реализованной возможностью.

Сервер слушает **только 127.0.0.1**. API проверяет Host, Origin и случайный
сессионный токен; токен не передаётся в URL, CORS не открыт. Пути загрузок
назначает сервер, артефакты выдаются по разрешённому списку. Просмотр результата
изолирован в iframe; данные не становятся HTML-кодом или исполняемыми правилами.
Это меры против случайной публикации и запросов чужого сайта, **не** полноценная
многопользовательская аутентификация или гарантия защиты от всех угроз.

Не публикуйте сервис через reverse proxy, туннель, внешний интерфейс или
общедоступный хостинг. Пользователь с доступом к учётной записи ОС имеет доступ
к файлам. Исходники, отчёты и HTML содержат финансовую сеть: обращайтесь с ними
как с данными и не загружайте в публичный репозиторий. Загружаемые скрипты,
выражения правил и произвольные модули не исполняются.

## Расширение без второго аналитического ядра

`workbench/importing.py` читает форматы и создаёт `Dataset`;
`workbench/analysis.py` проверяет профиль и строит результаты;
`workbench/server.py` отвечает за локальные загрузки и историю. Интерфейс мастера
не дублирует формулы ролей. Общие метрики, кластеризация и просмотр находятся
в `aml_graph/` и `web/`.

Следующий этап — универсальный CLI с конфигурационным файлом, вызывающий тот же
