# Демонстрационный набор данных

В исходной рабочей папке файлы соревнования отсутствовали. Поэтому этот каталог
содержит **детерминированный синтетический набор**, который повторяет публичную
схему и выбранные контрольные агрегаты из `AGENT.md`, но не все показатели
описанного исходного набора. Он нужен для воспроизводимой проверки пайплайна и
не должен выдаваться за оригинальные данные HackAlem.

Генерация:

```powershell
python scripts/generate_demo_data.py
```

Генератор использует только синтетические `gid` и поля, перечисленные ниже. В
наборе нет ФИО, ИИН, пола, возраста, дохода или иных клиентских атрибутов.

## `nodes.parquet`

Одна строка на узел, 2 248 строк.

| Поле | Тип | Описание |
|---|---|---|
| `gid` | int64 | Синтетический идентификатор узла |
| `depth` | int64 | Минимальное колено обхода, 0–4 |
| `is_seed` | bool | Признак стартового узла |

Распределение `depth`: 81 / 472 / 462 / 789 / 444 для уровней 0–4.

## `edges.parquet`

Одна строка на агрегированную направленную пару, 3 119 строк.

| Поле | Тип | Описание |
|---|---|---|
| `src` | int64 | Плательщик |
| `dst` | int64 | Получатель |
| `sum_kzt` | int64 | Сумма переводов пары за период |
| `n_tx` | int64 | Число переводов пары |
| `depth` | int64 | Колено получателя (`dst`) |

## `transactions.parquet`

Одна строка на синтетическую транзакцию, 4 840 строк.

| Поле | Тип | Описание |
|---|---|---|
| `src` | int64 | Плательщик |
| `dst` | int64 | Получатель |
| `date` | datetime64[ns] | Дата в июле 2026 года |
| `sum_kzt` | int64 | Сумма транзакции, не менее 5 000 KZT |

Сумма `sum_kzt` после агрегации транзакций равна 365 890 012 KZT.

## Расхождения с описанием исходного набора

Совпадают схема, число узлов/рёбер/транзакций, число seed, распределение глубин,
общий оборот и выбранная структура из 16 компонент. Синтетические связи не
восстанавливают оригинальную сеть, поэтому не все её заявленные характеристики
совпадают:

| Показатель | Текущая синтетика | Описано в DOCX |
|---|---:|---:|
| Узлы с наблюдаемым `sum_out > sum_in` | 869 | 354 |
| Seed, полностью отсутствующие в рёбрах | 0 | 19 |
| Seed только с входящими рёбрами | 31 | 12 |
| Узлы вне крупнейшей компоненты | 371 | 352 |

В исходном описании есть два противоречия, требующие уточнения у организаторов:

1. Заявлены ровно 16 слабосвязных компонент с размерами не меньше двух и
   19 seed, полностью отсутствующих в рёбрах. Каждый такой seed образовал бы
   отдельную изолированную компоненту. В синтетике приоритет отдан структуре
   из 16 компонент: все 31 seed без исходящих связаны с графом входящими рёбрами,
   отсутствующих в рёбрах seed нет. Это не воспроизведение условия о 19 seed.
2. При 2 248 узлах и крупнейшей компоненте из 1 877 узлов вне неё остаётся
   `2248 − 1877 = 371`, а не 352. Синтетический набор сохраняет эти два размера,
   а не несовместимое с ними число 352.

Ни данные, ни пороговые правила не подгоняются к 354/19/12/352. Отчёты и CSV,
сформированные по этим файлам, демонстрируют реализацию на синтетике, а не качество анализа
оригинальных данных. До окончательной приёмки нужно получить фактические
Parquet и согласовать противоречивые условия; успех локальных тестов этого
не заменяет.

## Маркировка источника в интерфейсе

`demo_manifest.json` хранит SHA-256 трёх демонстрационных parquet. Генератор
пересоздаёт manifest вместе с данными. Экран помечает набор как демонстрационный
только при совпадении всех хешей. При замене файлов или повреждении manifest
он просит проверить источник, а не объявляет новый набор оригинальным.
Это проверка соответствия локальному демонабору, не криптографическое
подтверждение авторства или подлинности входных данных.
